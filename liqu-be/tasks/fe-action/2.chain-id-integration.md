# FE Action: Integrate ChainId into Property, Market, and Portfolio API Calls

## Background
The backend has been updated to fully support multi-chain operations by dynamically fetching smart contract deployments (like `CH_PT`, `CH_USDC`, etc.) directly from the database based on the network the user is transacting on. 

As a result, all backend endpoints that interact with or query smart contracts now require a `chainId` parameter in their request paths or parameters. 

## Required Updates

### 1. Property Detail Endpoints
* **Action:** Pass `chainId` in the API path when fetching contract-specific property tx configurations.
* **Endpoints:**
  * `POST /v1/property/:id/yield/:chainId/create-tx`
  * `POST /v1/property/:id/yield/:chainId/submit`
  * `POST /v1/property/:id/register/:chainId/create-tx`
  * `POST /v1/property/:id/register/:chainId/submit`

### 2. Market Stat Endpoints
* **Action:** Pass `chainId` in the API path to retrieve market statistics.
* **Endpoints:**
  * `GET /v1/market/:tokenId/:chainId/stats`
  * `GET /v1/market/:tokenId/:chainId/price-history`

### 3. Portfolio Endpoints
* **Action:** Pass `chainId` in the API path when querying portfolio balances and claiming yields.
* **Endpoints:**
  * `GET /v1/portfolio/:chainId`
  * `POST /v1/portfolio/claim-yield/:chainId/create-tx`
  * `POST /v1/portfolio/claim-yield/:chainId/submit`

### 4. Other Contract-Interacting Endpoints
In addition to the main modules above, the following admin and utility endpoints have been refactored to require `chainId` in their request paths:

* **Admin Module**
  * `POST /v1/admin/:chainId/mint-asset` 
* **Factory Module**
  * `POST /v1/factory/:chainId/create-deploy-guard-tx`
  * `POST /v1/factory/:chainId/submit-deploy-guard-tx`
* **Mint Module**
  * `POST /v1/mint/:chainId/create-mint-principle-tx`
  * `POST /v1/mint/:chainId/submit-mint-principle`
* **Presale Module**
  * `POST /v1/presale/:chainId/create-presale-tx`
  * `POST /v1/presale/:chainId/submit-presale-tx`
  * `POST /v1/presale/:chainId/approve-usdc-presale`
* **Swap Module**
  * `POST /v1/swap/:chainId/create-swap-tx`
  * `POST /v1/swap/:chainId/submit-swap-tx`
* **Miscellaneous Module**
  * `POST /v1/misc/:chainId/approve-mint-principle`
  * `POST /v1/misc/:chainId/deal-usdc`

## Testing Notes
Make sure the `chainId` passed from the frontend is the active network ID that the user's wallet is currently connected to (for example, `84532` for Base Sepolia).

All these endpoints will now retrieve the exact contract deployed for that chain instead of relying on hardcoded addresses in the backend.
